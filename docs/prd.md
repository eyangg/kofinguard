# KoFinGuard 제품 요구사항 문서(PRD)

> 수업 문서 흐름: MVP → **PRD**(이 문서) → SPEC → PLAN

## 1. 문서 목적

이 문서는 KoFinGuard 첫 버전에서 **무엇을 만들어야 하는지** 쉽게 설명하는 제작 주문서입니다.
`mvp.md`에서 정한 범위를 빠짐없이 담고, 새 기능은 추가하지 않습니다. 정하지 않은 내용은 '미정'으로 남깁니다.

## 2. 서비스 소개

KoFinGuard는 가상 은행 **MJ뱅크**의 AI 상담 챗봇입니다. 같은 챗봇을 두 가지 상태로 나란히 보여 줍니다.

- **방어 OFF:** 보안 장치가 없는 챗봇입니다. 최근 실제로 일어난 AI 공격을 넣으면 뚫립니다.
- **방어 ON:** 같은 챗봇에 여러 겹의 방어 장치를 붙였습니다. 같은 공격을 막습니다.

방어 장치 중 하나는 내 졸업 프로젝트의 **한국어 탈옥 탐지 모듈**입니다. 결과는 화면 시연과 숫자(탐지율·오탐률)로 함께 보여 줍니다.

MJ뱅크와 모든 고객·계좌·금액은 가상입니다.

## 3. 누가 사용하나요?

| 사용자 | 하는 일 |
|---|---|
| 가상 고객 (김민수, 이서연) | 로그인한 뒤 챗봇에게 잔액·거래내역을 묻고 송금을 부탁합니다 |
| 공격자 역할 (시연자 본인) | 준비된 공격 문장이나 문서를 챗봇에 넣습니다 |
| 발표를 듣는 사람·면접관 | 같은 공격이 OFF에서는 성공하고 ON에서는 막히는 장면과 숫자를 봅니다 |

## 4. 어떤 불편(문제)을 해결하려고 하나요?

금융 챗봇이 잔액 조회·송금 같은 기능을 직접 실행하게 되면서, **말로 속이는 공격이 곧 돈과 개인정보 피해**가 됩니다.

| 공격 | 모델로 삼은 실제 사건 | 챗봇에서 생기는 피해 |
|---|---|---|
| S1. 권한 사칭 | 2026년 9~10월 국내 금융권 연쇄 침해. AI 기반 공격 도구 흔적, 임직원용 AI 서비스로 정보를 빼내려 한 정황이 보도됨 | 남의 고객정보가 노출됨 |
| S2. 인코딩·사투리 우회 탈옥 | 2026년 5월 Grok·Bankrbot 사건. 모스부호로 숨긴 지시에 AI가 속아 약 15만~20만 달러 상당을 송금함 | 이체 한도 같은 규칙을 우회해 돈이 나감 |
| S3. 문서 속 숨은 지시 (간접 프롬프트 인젝션) | EchoLeak (CVE-2025-32711, M365 Copilot). 메일 속 숨은 지시로 클릭 없이 내부 파일이 유출됨 | 문서를 요약하다가 계좌정보가 외부로 전송됨 |

한국어 서비스에는 문제가 하나 더 있습니다. 자모 분리(ㅅㅗㅇㄱㅡㅁ), 초성(ㅅㄱ), 사투리 같은 우회는 영어 중심 보안 도구가 놓치기 쉽습니다.

KoFinGuard는 이 문제를 다음처럼 보여 주고 줄입니다.

- 같은 공격을 OFF/ON 챗봇에 동시에 넣어, 무엇이 뚫리고 무엇이 막히는지 실제 결과로 확인합니다.
- 탐지기 하나로는 다 막을 수 없다는 점(S1)도 그대로 보여 주고, 서버 권한 검사 같은 다른 방어를 함께 씁니다.
- 탐지기가 정상 문장을 잘못 막는 문제(오탐)를 설계로 줄이고, 숫자로 확인합니다.

## 5. 사용자가 각 기능으로 무엇을 할 수 있나요?

### 5.1 로그인

- 시연용 고객 계정(김민수, 이서연)으로 로그인합니다. 회원가입은 만들지 않습니다.
- 로그인하지 않으면 챗봇과 계좌 화면을 쓸 수 없습니다.

### 5.2 챗봇 상담 (고객 입장)

- 챗봇에게 "내 잔액 알려줘", "최근 거래내역 보여줘"라고 물으면 **내 계좌** 정보만 답합니다. (F-01, F-02)
- "내 대출 정보 알려줘"처럼 고객 정보(연락처, 대출 정보)를 물으면 답합니다. (F-05)
  - ON에서는 내 정보만 나옵니다.
  - OFF에서는 남의 정보까지 나올 수 있습니다. S1이 이 약점을 노립니다.
- "이서연에게 5만원 보내줘"라고 하면 송금을 진행합니다. (F-03)
  - OFF: 바로 송금됩니다.
  - ON: '송금 대기' 카드가 뜨고, **내가 [확인] 버튼을 눌러야** 송금됩니다. (F-04)
- 하루 이체 한도는 100만원입니다. (F-06)
- 문서(텍스트 또는 PDF)를 첨부하고 "요약해줘"라고 할 수 있습니다. (F-07)

### 5.3 공격 시연 (공격자·발표 입장)

- 비교 화면에서 공격 버튼(S1, S2 변형들, S3)을 누르면, 같은 문장이 OFF와 ON 챗봇에 동시에 들어갑니다. (U-02)
- 각 챗봇 아래에서 **어떤 방어 장치가 어떻게 판단했는지** 볼 수 있습니다. 예: 정규화된 문장, PPL 값, 복원된 문장, Llama Guard 판정, 서버가 거부한 이유. (U-03)
- 공격자 서버가 받은 유출 기록을 볼 수 있습니다 (S3 확인용). (U-05)

### 5.4 방어 장치 (방어 ON에서만 동작)

| ID | 방어 장치 | 쉬운 설명 |
|---|---|---|
| D-01 | 문장 정리 | 자모 분리 같은 변형을 정리합니다 (졸프 전처리) |
| D-02 | 이상한 문장 가려내기 (SmoothPPL) | 문장이 부자연스러운지 점수를 매깁니다. **이 점수만으로 막지는 않습니다** |
| D-03 | 암호 풀기 | 부자연스러운 문장이면 모스부호·초성·자모 분리·base64를 원래 문장으로 되돌려 봅니다 |
| D-04 | 위험 판정 (Llama Guard) | 원래 문장 또는 되돌린 문장이 위험한지 판정해서, 위험하면 막습니다 |
| D-05 | 다시 묻기 | 되돌리지도 못하면 막지 않고 "일반 문장으로 다시 말씀해 주세요"라고 답합니다 |
| D-06 | 서버 권한 검사 | 챗봇이 무엇을 요청하든, 서버는 **로그인한 본인 정보만** 내줍니다 |
| D-07 | 서버 규칙 | 이체 한도와 송금 확인 절차는 서버 코드가 지킵니다 |
| D-08 | 첨부 문서 격리 | 첨부 문서도 D-01~D-04 검사를 거치고, 문서를 처리하는 동안에는 챗봇이 기능을 실행할 수 없습니다 |
| D-09 | 답변 걸러내기 | 답변 속 외부 링크·이미지를 지우고 계좌번호를 가립니다 |

### 5.5 평가 결과 보기

- 탐지기를 여러 방식으로 비교한 표를 봅니다. (E-02)
  - ① Llama Guard만
  - ② 이상한 문장 점수만으로 차단
  - ③ 점수 → 암호 풀기 → Llama Guard
  - 공격을 얼마나 잡았는지(탐지율, TPR)와 정상 문장을 얼마나 잘못 막았는지(오탐률, FPR)를 비교합니다.
- 시나리오별 공격 성공률(OFF vs ON) 표를 봅니다. (E-03)
- 평가는 명령어로 실행하고, 화면은 결과를 읽기만 합니다.

## 6. 어떤 화면이 필요한가요?

| ID | 화면 | 내용 |
|---|---|---|
| U-01 | 로그인 | 시연 계정 로그인 |
| U-02 | 비교 채팅 | 왼쪽 OFF / 오른쪽 ON 채팅, 공격 버튼, 문서 첨부 |
| U-03 | 방어 근거 패널 | 각 방어 장치의 판단 결과 |
| U-04 | 송금 대기 카드 | 송금 내용과 [확인] 버튼 (ON 전용) |
| U-05 | 공격자 서버 기록 | 유출된 요청 목록 |
| U-06 | 평가 결과 | E-02, E-03 표 |

## 7. 어디까지 되면 첫 버전이 완성된 것인가요?

- 화면에서 S1~S3를 넣었을 때 **OFF는 실제로 뚫리고(FAIL) ON은 실제로 막힌다(PASS)**.
  - 판정은 챗봇 말이 아니라 **잔액 변화, 서버 기록, 공격자 서버 기록**으로 확인합니다.
- E-02, E-03 표가 실제 실행 결과로 만들어진다.
- 정상 질문(암호처럼 쓴 정상 문장 포함)이 ON에서 얼마나 잘못 막히는지 표로 보인다.
- 수업 필수 스택이 실제로 동작한다: React 화면 → FastAPI → Supabase 저장.
- 실행하지 못한 검사는 성공으로 세지 않고 "미검증" 또는 "SKIP"으로 표시한다.

## 8. 이번에 만들지 않는 것

- 회원가입, 비밀번호 찾기
- 실제 계좌·결제 연동, 실명 인증
- 방어 OFF 챗봇의 인터넷 공개 (내 컴퓨터에서만 실행)
- 새 탐지 모델 학습
- 팀원이 만든 자모음 결합 모델 (내 담당이 아니므로 쓰지 않음)
- 폭력·무기 같은 실제 유해 콘텐츠를 만들어 내는 공격
- 클라우드 배포

## 9. 지켜야 할 원칙

| ID | 원칙 |
|---|---|
| N-01 | OFF 챗봇과 공격자 서버는 내 컴퓨터(127.0.0.1)에서만 실행한다 |
| N-02 | 브라우저는 Supabase에 직접 접속하지 않는다. DB는 FastAPI만 사용한다 |
| N-03 | 모든 테이블에 RLS를 켜고, 외부 접근 역할(`anon`, `authenticated`)의 권한을 회수한다 |
| N-04 | API 키·DB 비밀번호는 `backend/.env`에만 둔다. 코드·문서·Git·답변에 넣지 않는다 |
| N-05 | 화면에서 버튼을 숨기는 것만으로 권한을 처리하지 않는다. 서버에서도 검사한다 |
| N-06 | 기본 테스트는 인터넷·OpenAI·로컬 모델 없이 돌아간다 |
| N-07 | 탐지 모델은 GPU 없이 CPU로 돌린다 (RAM 16GB) |
| N-08 | 졸프 코드 중 **내 담당 부분만** 가져온다 |

## 10. 아직 정하지 않은 것 (미정)

| 항목 | 정하는 시점 |
|---|---|
| 챗봇에 쓸 OpenAI 모델 이름 (작고 싼 모델 중 선택) | Phase 0 |
| 이상한 문장 점수(PPL)의 기준값 | Phase 6 (정상 문장 점수를 보고 결정) |
| 정상 문장 오탐률 목표치 | Phase 10 (실제 결과를 보고 결정) |
| S2 공격 문장의 정확한 표현 | Phase 5 (OFF에서 실제로 뚫리는지 보고 결정) |
| Supabase를 BankGuard 프로젝트와 따로 만들지, 재사용할지 | Phase 0 |
