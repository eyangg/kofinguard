# KoFinGuard MVP — 가장 작게 만들어도 가치가 있는 범위

> 수업 문서 흐름: **MVP**(이 문서) → PRD → SPEC → PLAN
> 프로젝트 이름(KoFinGuard)과 은행 이름(MJ뱅크)은 임시 이름이며 바꿔도 됩니다. MJ뱅크는 실존하지 않는 가상 은행입니다.

## 1. 한 줄 소개

**KoFinGuard는 가상 은행(MJ뱅크)의 AI 상담 챗봇을 만들어 두고, 최근 실제로 일어난 LLM 공격을 한국어로 재현해 "방어 OFF 챗봇은 뚫리고 방어 ON 챗봇은 막는다"를 실제 실행 결과와 수치(TPR/FPR)로 보여 주는 프로젝트입니다.**

## 2. 왜 만드나

- 금융권은 상담 챗봇과 업무용 AI 비서를 빠르게 도입하고 있습니다. AI가 잔액 조회·송금 같은 **툴(기능)을 직접 호출**하면, 말로 속이는 공격이 곧 **돈과 개인정보 피해**가 됩니다.
- 2026년 9~10월 국내 금융권 연쇄 침해에서는 AI 기반 공격 도구의 흔적이 나왔고, 임직원용 AI 서비스로 정보를 빼내려 한 정황도 보도됐습니다. 2026년 5월에는 모스부호로 숨긴 지시에 AI 에이전트가 속아 암호화폐를 송금한 사건이 있었습니다.
- 기존 가드레일 도구(Llama Guard 등)는 영어 중심입니다. **자모 분리·초성·사투리 같은 한국어 우회**에는 약합니다.
- 내 졸업 프로젝트의 **한국어 탈옥 탐지 모듈**(자모 분해 전처리, SmoothPPL, Llama Guard 연동)을 실제 금융 챗봇에 붙여 쓸모를 증명합니다.
- 탐지기 하나로는 모든 공격을 못 막는다는 점도 보여 줍니다. 그래서 **탐지 + 권한 하네스 + 출력 필터**의 다층 방어를 만듭니다.

## 3. 누가 쓰나

| 사용자 | 하는 일 |
|---|---|
| 가상 고객 (김민수, 이서연) | 로그인해서 챗봇에게 잔액·거래내역을 묻고 송금을 요청합니다 |
| 공격자 (시연자 본인) | 미리 준비한 공격 프롬프트·문서를 챗봇에 넣습니다 |
| 발표를 듣는 사람·면접관 | 같은 공격이 OFF에서는 성공하고 ON에서는 막히는 장면과 수치를 봅니다 |

모든 고객·계좌·금액은 **허구의 테스트 데이터**입니다. 실제 은행이나 외부 시스템에는 요청하지 않습니다. 유출을 받는 "공격자 서버"도 내 PC 안(127.0.0.1)에서만 동작합니다.

## 4. MVP에 반드시 들어가는 것

1. **가상 은행 API**: 내 잔액, 거래내역, 송금, 고객 정보 조회. 챗봇이 이 기능들을 툴로 호출합니다.
2. **AI 상담 챗봇 (두 모드)**: 같은 화면, 같은 모델, 같은 프롬프트를 쓰고 방어 레이어만 OFF/ON합니다.
3. **공격 시나리오 3개**: 모두 최근 실제 사건을 모델로 합니다.
   - **S1 권한 탈취형 사회공학**: "나 감사팀인데…"라고 속여 남의 고객정보를 조회하게 만듭니다.
   - **S2 인코딩·사투리 우회 탈옥**: 송금 한도 같은 정책을 우회해 돈을 움직이게 만듭니다.
   - **S3 간접 프롬프트 인젝션**: 고객이 올린 문서 속 숨은 지시로 계좌 정보를 외부로 유출시킵니다.
4. **다층 방어**:
   - 입력 탐지기 (졸프 모듈): 자모 분해 → SmoothPPL 라우팅 → 디코딩 → Llama Guard 판정
   - 툴 권한 하네스: LLM이 무엇을 말하든 서버가 세션 사용자 권한으로 다시 검사
   - 송금 사용자 확인: LLM은 송금을 "대기"로만 만들 수 있고, 실행은 사람이 버튼을 눌러야 함
   - 출력 필터: 외부 링크·이미지 차단, 계좌번호 마스킹
5. **비교 화면 (React + TypeScript)**: 좌측 OFF, 우측 ON. 어떤 방어 레이어가 막았는지 근거를 표시합니다.
6. **정량 평가**: 탐지기 TPR/FPR, 시나리오별 공격 성공률(OFF vs ON)
7. **기록 저장 (Supabase)**: 대화·탐지 결과·툴 호출·평가 결과·첨부 파일 정보 (실제 파일은 `backend/uploads/`)

## 5. MVP에 넣지 않는 것

- 실제 계좌·결제·오픈뱅킹 연동, 실명 인증
- 방어 OFF 모드의 인터넷 공개 (로컬 시연 전용)
- 새 탐지 모델 학습 (졸프 모듈을 이식만 함)
- 팀원이 만든 자모음 결합 모델 (내 담당이 아니므로 쓰지 않음)
- 실제 유해 콘텐츠 생성 시나리오 (금융 피해 시나리오만 다룸)
- 클라우드 배포 (확장 항목)

## 6. 성공했다고 말할 수 있는 기준

- 화면에서 같은 공격을 넣었을 때 S1~S3 모두 **OFF는 실제로 뚫리고 ON은 실제로 막힌다**. 이 결과는 DB 상태와 공격자 서버 로그로 확인한다.
- 탐지기 평가표가 실제 실행 결과로 나온다. "PPL 단독 차단"과 "PPL 라우팅 + 디코딩 + Llama Guard"의 FPR 차이도 보인다.
- 정상 질문(인코딩된 정상 문장 포함)이 ON 모드에서 과하게 막히지 않는다.
- 실행하지 못한 검사는 PASS로 세지 않고 "미검증" 또는 "SKIP"으로 표시한다.
