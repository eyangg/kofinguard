# KoFinGuard 바이브코딩 진행 가이드 (프롬프트 모음)

> 수업 교안(01~09강)에 나온 프롬프트를 KoFinGuard에 맞게 바꾼 것입니다. **위에서부터 순서대로** 쓰면 됩니다.
> 각 프롬프트는 VS Code의 Claude Code(또는 Codex) 대화창에 그대로 복사해 넣습니다. `[ ]` 부분만 내 상황에 맞게 바꿉니다.
> 이미 만들어 둔 것(폴더 뼈대 일부, mvp·prd·spec·plan, CLAUDE.md)은 "새로 만들기" 대신 "확인하기" 프롬프트로 바꿨습니다.

## 1. 시작 전에 한 번만 하는 것

### 1-1. 프로젝트 열고 AI가 읽을 수 있는지 확인 (01강)

**언제:** VS Code에서 `kofinguard` 폴더를 처음 열었을 때

```text
현재 프로젝트의 CLAUDE.md와 docs 폴더의 mvp.md를 읽고, 이 프로젝트가 무엇인지 세 줄로 설명해줘. 아직 파일은 수정하지 마.
```

### 1-2. 작업 규칙 파일 확인 (05강)

**언제:** 1-1 다음

```text
프로젝트 바로 아래의 CLAUDE.md는 앞으로 개발할 때 지킬 작업 규칙이야.
CLAUDE.md를 읽고 docs의 prd.md·spec.md·plan.md와 충돌하는 부분이 있는지 확인해줘.
충돌이 있으면 고칠 방법만 제안하고, 이번에는 아무 파일도 수정하지 마.
```

### 1-3. 기획 문서 검토 (02·03강의 MVP·PRD·SPEC·PLAN 프롬프트를 '검토'로 바꿈)

**언제:** 1-2 다음. 문서는 이미 있으니 새로 만들지 않고 빈틈만 찾습니다.

```text
docs의 mvp.md → prd.md → spec.md → plan.md 순서로 읽어줘.
1. 네 문서의 기능 범위가 서로 맞는지 확인해줘.
2. prd.md 10장 '미정'과 spec.md의 '확인 필요' 항목을 모아서 나에게 하나씩 질문해줘.
3. 내가 답하면 해당 문서에만 반영해줘.
새 기능을 임의로 추가하지 말고, 지금은 문서만 다루고 코드 작성이나 설치는 하지 마.
```

### 1-4. Git 저장소 만들기 (04강 실습 1)

**언제:** 문서 검토가 끝났을 때

```text
현재 열려 있는 kofinguard 프로젝트를 Git으로 관리하려고 해.
Git이 설치되어 있는지, 이 폴더가 이미 Git 저장소인지, 기존 커밋이나 연결된 GitHub 주소가 있는지 확인해줘.
처음이라면 이 프로젝트 폴더에만 Git을 초기화해줘.
.gitignore가 없다면 .env와 .env.*, .venv, node_modules, dist, __pycache__, 로그 파일, models/, artifacts/, backend/uploads/, capstone_ref/, SQLite 파일을 제외하도록 만들어줘. .env.example은 기록할 수 있게 해줘.
이번에 저장할 파일 목록과 Git에서 제외할 파일을 쉽게 설명해줘. 아직 commit과 push는 하지 마.
```

> 처음이라면 Git Bash에서 `git config --global user.email "이메일"`, `git config --global user.name "이름"`을 먼저 설정합니다.

### 1-5. 첫 커밋 (04강 실습 2)

```text
지금까지 만든 기획 문서와 작업 규칙 파일을 첫 저장점으로 남겨줘.
변경 내용을 확인하고, 이번 작업에 해당하는 파일만 add한 뒤 commit해줘.
비밀번호나 API 키가 들어 있는 파일은 포함하지 마.
커밋 메시지는 '기획 문서와 작업 규칙 저장'으로 해줘.
작성자 이름과 이메일 설정이 필요하면 나에게 물어봐. 아직 push는 하지 마.
끝나면 저장한 파일과 커밋 번호를 알려줘.
```

### 1-6. GitHub에 올리기 (04강 실습 3)

VS Code 왼쪽 '소스 제어' → **Publish to GitHub** → **private(비공개)** 를 선택합니다.
공격 시나리오가 들어가는 프로젝트라 비공개를 권장합니다.

## 2. Phase 진행 (Phase마다 반복)

### 2-1. Phase 시작 전 (03강 3절)

**언제:** 처음 개발을 시작할 때 (Phase 0)

```text
이제 plan.md를 토대로 Phase별로 개발을 시작할거야.
일단 어떤 순서대로 개발을 하는지 Phase를 쭉 리스트업해줘.
그 다음 첫 번째로 수행할 내용을 보여준 다음, 실제 진행하기 전에 내가 줘야 할 값이나 따로 설정할 내용이 있는지 먼저 알려줘.
```

### 2-2. 다음 Phase로 넘어갈 때 / 대화를 새로 열었을 때 / 다음 날 이어서 할 때 (04강 5절)

```text
현재 우리가 어디 Phase까지 수행했지? plan.md 7장 진행 기록과 실제 파일을 확인한 다음에, 그 다음 할 Phase가 뭔지, 내가 처리해야 할 사항이 있는지 보고해.
```

### 2-3. Phase 실행

**언제:** AI가 알려준 '내가 할 일'을 다 끝낸 뒤

```text
Phase [번호] 진행해줘. plan.md의 해당 Phase 작업과 완료 조건만 하고, 끝나면 테스트 결과를 보고하고 멈춰.
```

### 2-4. 직접 실행해 보기 (06강 1-5)

**언제:** Phase 1 이후, 화면·서버를 직접 확인해야 할 때

```text
현재 프로젝트에서 백엔드, 프론트, (필요하면) 공격자 서버를 직접 켜볼게.
실제 파일과 README를 읽고 각각 실행할 폴더, 필요한 설치 명령, 실행 명령, 브라우저에서 열 주소를 알려줘.
이미 실행 중인 서버가 있는지도 확인하고, DB 설정이나 Ollama가 없어서 실행할 수 없다면 필요한 준비를 먼저 알려줘.
새 기능을 만들지는 말고, 프로그램은 내가 VS Code 터미널에서 직접 켤게.
```

포트가 이미 쓰이고 있다는 오류가 나면 이렇게 보냅니다.

```text
[포트 번호]번으로 서버를 켜려는데 이미 사용 중이라는 오류가 나와. 어떤 프로그램이 쓰고 있는지 확인하는 방법과 안전하게 끄는 방법을 알려줘. 내가 직접 끌게.
```

### 2-5. Phase 끝: 확인 → 학습 기록 → 커밋·푸시 (04강)

1. AI가 보고한 '내가 확인할 것'을 직접 확인합니다.
2. `docs/learning_log.md`에 이해한 것 3줄을 내가 직접 씁니다.
3. 아래 프롬프트를 보냅니다.

```text
Phase [번호] 확인 끝났고 learning_log도 썼어.
이번 Phase 관련 변경만 add해서 commit하고 push해줘. 커밋 메시지는 plan.md의 해당 Phase 내용으로 짧게 써줘.
.env나 키가 들어간 파일이 포함되지 않았는지 먼저 확인해줘. 끝나면 커밋 번호를 알려줘.
```

### 3-1. Phase 5: OpenAI 키 연결 (08강 5절)

**언제:** Phase 5를 시작할 때 (2-1·2-3 대신 또는 함께)

```text
이번에는 MJ뱅크 챗봇에 OpenAI를 연결할거야. key는 내가 결제해서 가지고 있어.
나는 backend/.env에 key만 넣으면 바로 실행되게 하고 싶어.
(1) 고객이 메시지를 보내면 내부적으로 OpenAI를 호출하고, spec.md 3장의 툴(잔액·거래·고객 정보·송금 요청)을 쓸 수 있게 한다.
(2) 너무 비싼 모델을 쓰지 않고, 모델 이름은 .env의 OPENAI_MODEL로 정한다. temperature는 0, 최대 답변 길이는 OPENAI_MAX_TOKENS.
(3) 테스트에서는 실제 OpenAI 대신 가짜 LLM을 써서 인터넷 없이 돌아가게 한다.
(4) key를 코드·로그·답변에 출력하지 않는다.
위 내역을 현재 코드에 녹이기 위해 어떻게 구현해야 할지 plan을 짜봐. 구현은 아직 하지 마.
```

plan이 나오면 순서대로 보냅니다.

```text
위 플랜을 토대로 어떻게 개발해야 하는지 상세한 SDD를 짜봐
```

```text
plan.md의 Phase 5에 맞춰 위 SDD를 반영해서 개발 진행해. 끝나면 내가 .env에 넣을 항목과 실행 확인 방법을 알려줘.
```

> 키는 내가 직접 `backend/.env`에 붙여 넣습니다. **채팅에 키를 붙여 넣지 않습니다.** 환경설정값은 서버를 다시 켜야 반영됩니다.

### 3-4. Phase 8: Supabase 연결 (06강 3절)

```text
현재 프로젝트에서 사용 중인 SQLite를 Supabase의 PostgreSQL로 변경하려고 해.
먼저 기존 DB 연결 코드, 테이블 구조, Alembic 설정을 확인하고, 내가 backend/.env에 DB 연결 정보만 넣으면 사용할 수 있도록 준비해줘.
다음 내용을 반영해줘.
1. 기존 로그인·은행·챗봇 기록 기능과 테이블 구조를 유지하면서 PostgreSQL에서 동작하도록 수정해줘. 필요한 패키지도 설치해줘.
2. DB 연결 정보는 backend/.env의 DATABASE_URL에서 읽도록 해줘. 실제 값은 내가 직접 입력할 테니, .env.example에는 입력할 항목과 설명을 작성해줘. Supabase의 Session pooler 연결 정보를 사용할 예정이야.
3. .env 설정이 없거나 잘못됐다면 무엇을 확인해야 하는지 알려줘. 이때 SQLite로 자동 연결하지는 마.
4. 기존 Alembic을 활용해, 내가 DB 연결 정보를 입력한 뒤 명령 하나를 실행하면 필요한 테이블이 생성되도록 준비해줘. 이미 적용한 변경은 다시 적용되지 않도록 해줘.
5. 모든 테이블에 RLS를 켜고 anon·authenticated 역할의 테이블 권한을 회수하는 마이그레이션도 넣어줘.
6. 테스트는 계속 임시 SQLite로 인터넷 없이 돌아가게 하고, Supabase 테스트는 pytest -m postgres로 따로 해줘.
7. .env가 Git에 올라가지 않도록 확인하고, 비밀번호와 전체 연결 문자열은 답변이나 로그에 출력하지 마.
준비가 끝나면 다음 세 가지를 쉽게 알려줘.
- .env를 어느 폴더에 만들고 어떤 값을 넣어야 하는지
- 테이블을 준비할 때 어느 폴더에서 어떤 명령을 실행하는지
- 서버를 다시 켜고 로그인·챗봇 대화로 연결을 확인하는 방법
아직 연결 정보를 입력하지 않았으니, 실제 DB 연결이나 테이블 생성이 완료됐다고 보고하지 마. 이번 변경과 관계없는 화면과 기능은 수정하지 마.
```

> Supabase 대시보드 → Connect → Session pooler → 연결 문자열 복사 → `[YOUR-PASSWORD]`를 실제 비밀번호로 바꿔서 `backend/.env`의 `DATABASE_URL`에 넣습니다.

### 3-5. Phase 9: Figma로 화면 정하고 React에 반영 (07강)

```text
Figma MCP가 연결되어 있는지 확인해줘. 사용할 수 있는 Figma 도구 이름을 알려줘. 연결이나 인증 문제가 있다면 무엇이 필요한지 알려줘. 아직 디자인이나 프로젝트 파일은 수정하지 마.
```

```text
방금 Figma MCP로 읽은 비교 채팅 화면을 현재 프로젝트의 React + TypeScript 화면으로 구현해줘.

spec.md 6장대로 실제 백엔드 API(/api/chat, /api/demo/presets 등)에 연결해줘.
OFF 패널은 마크다운 이미지를 그리고, ON 패널은 이미지와 링크를 그리지 않게 해줘.
백엔드·DB·환경변수는 변경하지 마. 완료 후 npm run build로 확인하고, 내가 실행할 명령과 폴더, 브라우저 주소를 알려줘.
```

```text
아래 Figma 디자인을 MCP로 다시 읽고, 현재 구현된 화면과 비교해줘.
```

## 4. 아무 때나 쓰는 프롬프트

### 4-1. 오류가 났을 때 (09강)

**순서:** 화면 → Console(F12) → Network(F12) → 백엔드 터미널 순으로 단서를 찾고, **찾은 증거를 그대로 붙여** 보냅니다.

화면·Console 오류 (프론트 문제):

```text
[Console에 나온 오류 메시지 그대로 붙여넣기]
다음과 같이 오류가 발생했어. 원인을 분석해서 알려줘.
참고로 화면 http://localhost:5173/[경로]에서 [어떤 버튼]을 눌렀을 때 발생한 문제야.
```

Network 404 (주소 문제):

```text
[어떤 버튼]을 누르면 Network에서 404 오류가 발생해.
Request URL: [주소], Method: [GET/POST], Status: 404
해당 원인을 분석해봐. 고치기 전에 원인부터 알려줘.
```

백엔드 500 (서버 코드 문제):

```text
[백엔드 터미널의 Traceback 그대로 붙여넣기]
다음과 같이 오류가 발생했어. 해당 오류의 원인과 위치를 확인해서 뭐가 문제고 어떻게 고쳐야 하는지 상세히 설명해줘.
```

> 오류 메시지에 API 키나 DB 비밀번호가 보이면 그 부분은 지우고 붙여 넣습니다.
