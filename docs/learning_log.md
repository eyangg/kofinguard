# KoFinGuard 학습 기록 (learning_log)

> 각 Phase가 끝날 때 **내가 직접** 쓰는 기록입니다. AI가 대신 쓰지 않습니다.
> 이 기록을 쓰고 화면을 확인한 뒤에 커밋하고, "다음"이라고 해야 다음 Phase로 넘어갑니다 (`docs/plan.md` 2장, `docs/workflow.md` 2-5).

## 작성 형식

```markdown
## YYYY-MM-DD · Phase X

**이해한 것 (3줄)**
Q1. 왜 프론트는 /api만 부르고, Vite가 8000으로 넘겨 주나?
A. 화면(5173)과 백엔드(8000)는 포트가 달라서 브라우저가 다른 사이트로 보고 요청을 막는다(CORS). 그래서 화면은 같은 주소의 /api만 부르고 Vite가 뒤에서 8000으로 전달한다. 브라우저는 백엔드 한 곳만 알게 되니까 DB 비밀번호와 API 키는 백엔드 안에만 있고, 권한 검사도 서버가 하게 된다.

Q2. 왜 .env는 Git에서 빼고 .env.example만 올리나?
A. .env에는 OpenAI 키와 DB 비밀번호 같은 진짜 비밀값이 있고, 한 번 GitHub에 올라가면 지워도 커밋 기록에 남아 도용될 수 있다. .env.example은 항목 이름과 설명만 있는 안내서라서, 다른 PC에서도 무엇을 채워야 하는지 알 수 있다. 그래서 .gitignore로 .env만 막고 .env.example은 허용한다.

Q3. 왜 기본 pytest는 모델이나 OpenAI 없이 돌아야 하나?
A. 실제 AI를 부르면 돈이 들고, 느리고, 매번 답이 달라서 테스트 결과가 들쭉날쭉해진다. 가짜 LLM은 항상 똑같이 움직이니까 내 코드가 맞는지만 빠르게 확인할 수 있고, 인터넷이나 키가 없는 곳에서도 돌아간다. 실제 모델 검사는 -m models나 -m llm으로 따로 표시해 두고 필요할 때만 돌린다.

**아직 모르는 것**
-
```

- **이해한 것:** 이번 Phase에서 만든 것이 *왜* 그렇게 동작하는지 내 말로 씁니다.
  - 예) "PPL을 차단기로 쓰면 자모나 사투리로 쓴 정상 문장도 막히기 때문에, 차단은 Llama Guard가 하고 PPL은 다시 물을지 판단하는 데만 쓴다."
- **아직 모르는 것:** 설명하라고 하면 막힐 부분을 적습니다. 다음 Phase 전에 AI에게 물어보거나 직접 찾아봅니다.
