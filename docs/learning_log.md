# KoFinGuard 학습 기록 (learning_log)

> 각 Phase가 끝날 때 **내가 직접** 쓰는 기록입니다. AI가 대신 쓰지 않습니다.
> 이 기록을 쓰고 화면을 확인한 뒤에 커밋하고, "다음"이라고 해야 다음 Phase로 넘어갑니다 (`docs/plan.md` 2장, `docs/workflow.md` 2-5).

## 작성 형식

```markdown
## 2026-10-30 · Phase 1

**이해한 것 (3줄)**
Q1. 왜 프론트는 /api만 부르고, Vite가 8000으로 넘겨 주나?
A. 화면(5173)과 백엔드(8000)는 포트가 달라서 브라우저가 다른 사이트로 보고 요청을 막는다(CORS). 그래서 화면은 같은 주소의 /api만 부르고 Vite가 뒤에서 8000으로 전달한다. 브라우저는 백엔드 한 곳만 알게 되니까 DB 비밀번호와 API 키는 백엔드 안에만 있고, 권한 검사도 서버가 하게 된다.

Q2. 왜 .env는 Git에서 빼고 .env.example만 올리나?
A. .env에는 OpenAI 키 와 DB 비밀번호 같은 진짜 비밀값이 있고, 한 번 GitHub에 올라가면 지워도 커밋 기록에 남아 도용될 수 있다. .env.example은 항목 이름과 설명만 있는 안내서라서, 다른 PC에서도 무엇을 채워야 하는지 알 수 있다. 그래서 .gitignore로 .env만 막고 .env.example은 허용한다.

Q3. 왜 기본 pytest는 모델이나 OpenAI 없이 돌아야 하나?
A. 실제 AI를 부르면 돈이 들고, 느리고, 매번 답이 달라서 테스트 결과가 들쭉날쭉해진다. 가짜 LLM은 항상 똑같이 움직이니까 내 코드가 맞는지만 빠르게 확인할 수 있고, 인터넷이나 키가 없는 곳에서도 돌아간다. 실제 모델 검사는 -m models나 -m llm으로 따로 표시해 두고 필요할 때만 돌린다.


Phase 2

Q1. 왜 테이블을 직접 만들지 않고 Alembic 명령으로 만드나?
A. 테이블 구조를 코드(마이그레이션 파일)로 남겨 두면, 내 PC의 SQLite든 나중의 Supabase든 명령 하나(upgrade head)로 똑같이 만들 수 있다. 이미 적용한 변경은 alembic_version에 기록돼서 다시 실행해도 중복으로 만들지 않는다.

Q2. 왜 DATABASE_URL이 없으면 SQLite로 넘어가지 않고 멈추나?
A. 설정이 빠졌는데 몰래 SQLite로 넘어가면, Supabase에 저장되는 줄 알았던 시연 데이터가 실제로는 내 PC 파일에만 쌓이는 사고가 난다. 멈추고 무엇을 확인할지 알려 주는 게 더 안전하다.

Q3. 왜 비밀번호를 원문이 아니라 해시로 저장하나?
A. 해시는 되돌릴 수 없는 변환이라 DB가 유출돼도 원래 비밀번호를 알 수 없다. 로그인할 때는 입력한 비밀번호를 같은 방식으로 해시해서 저장된 값과 비교만 한다. 사람마다 다른 소금값(salt)을 섞어서 같은 비밀번호라도 저장값이 달라진다.
```
